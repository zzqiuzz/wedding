# 婚礼邀请网站设计文档

## 项目概述

**网站域名**：lepaulski.asia

**新人**：郑哲 & 陆琳娜

**婚礼信息**：
- 日期：2026年10月25日
- 时间：12:08
- 地点：灌云县伊山镇皇冠世纪酒店

**项目目标**：创建单页面婚礼邀请网站，提供RSVP登记、实时出席人数统计、婚礼信息展示和迎宾区设计图展示。

## 技术栈与架构

### 架构
单页面应用（SPA），前端静态部署，后端使用BaaS（Backend as a Service）

### 技术选型
- **前端**：HTML5 + CSS3 + Vanilla JavaScript（轻量，无需框架）
- **部署**：Vercel（前端静态托管，自动HTTPS，绑定域名lepaulski.asia）
- **后端/数据库**：Supabase（免费tier）
  - PostgreSQL数据库存储RSVP数据
  - Realtime功能实现出席人数实时更新
- **地图**：高德地图API（国内访问稳定）嵌入婚礼地点

### 数据流
1. 客人访问lepaulski.asia
2. 填写RSVP表单 → 数据存入Supabase
3. Supabase Realtime推送更新 → 页面实时显示最新出席人数

单页面滚动布局，共4个区块：

### 1. Hero区域（首屏）

- 婚礼时间：12:08
- 倒计时器（距离婚礼还有X天，显示天:时:分:秒）

### 2. 婚礼详情区块
- 标题：婚礼详情
- 地点：灌云县伊山镇皇冠世纪酒店
- 嵌入高德地图（显示酒店位置，可点击导航）

### 3. 迎宾区设计图区块

  - 姓名（文本输入，必填）

## 响应式设计

### 移动优先设计
- 大部分客人使用手机访问
- 断点设置：
  - 移动端：< 768px
  - 平板：768px - 1024px
  - 桌面：> 1024px

### 布局适配
- **移动端**：单列布局，表单输入框和按钮加大（min-height: 44px）方便触摸操作
- **桌面端**：内容区域最大宽度900px居中，适当留白

### 倒计时器响应式
- 移动端：2x2网格布局
- 桌面端：水平排列

## 数据模型

### Supabase数据库表结构

```sql
create table rsvp (
  id bigint generated by default as identity primary key,
  name text not null,
  guests integer not null check (guests >= 1 and guests <= 10),
  phone text not null check (phone ~ '^[0-9]{11}$'),
  created_at timestamp with time zone default now()
);

-- 启用Realtime订阅
alter publication supabase_realtime add table rsvp;
```

### RSVP提交流程
1. 客人填写表单（姓名、人数、手机号）
2. 前端验证：
   - 姓名非空
   - 手机号11位数字
   - 人数已选择（1-10）
3. 提交 → Supabase插入数据
4. 成功：显示成功消息 + 更新实时人数
5. 失败：显示错误提示

### 实时人数统计
- 使用Supabase Realtime订阅rsvp表的INSERT事件
- 每次新登记，前端自动重新计算总人数（SUM(guests)）
- 显示格式："已确认出席 X 人"
- 显示位置：RSVP表单上方，醒目展示

## 部署方案

### 前端部署（Vercel）
1. 代码推送到Git仓库
2. Vercel连接仓库，自动部署
3. 绑定域名lepaulski.asia：
   - 在Vercel中添加自定义域名
   - 在域名服务商设置DNS记录（CNAME或A记录）

### Supabase设置
1. 创建Supabase项目
2. 执行数据库建表SQL
3. 获取API密钥（URL和anon key）
4. 前端环境变量配置

### 高德地图
1. 申请高德地图API Key
2. 嵌入地图组件到婚礼详情区块

## 成功标准

1. 用户可成功提交RSVP，数据正确存入数据库
2. 实时人数统计准确，新提交后自动更新
3. 网站在移动端和桌面端都能正常显示和操作
4. 倒计时器正确显示距离婚礼的时间
5. 地图正确显示酒店位置
6. 迎宾区设计图可正常展示和放大查看
7. 域名lepaulski.asia可正常访问（HTTPS）
